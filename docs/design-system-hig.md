## 0. 먼저 짚을 충돌 (Rule 7)

Apple HIG는 네이티브 iOS/macOS 관용구를 전제한다. SF Pro, Dynamic Type, 탭 바, 시스템 제스처, 44pt 타깃, 시스템 머티리얼.
이 프로젝트는 다크 매트릭스 테마의 **웹 랜딩 사이트**다. `Perfect DOS VGA 437` 모노스페이스, `#000` 그라운드, 1508px 컨테이너, blur 기반 `.slideIn` 등장.

두 체계를 평균내면 둘 다 망가진다. 선택은 아래와 같다.

| HIG 항목 | 판정 | 근거 |
|---|---|---|
| 타깃 44pt 최소 | **채택** | 플랫폼 무관. 실제 결함이었다 |
| 명확한 포커스 링 | **채택** | WCAG 2.4.7 강제 |
| 상태 완결성 (loading / empty / error) | **채택** | 결함이었다 |
| Dynamic Type (상대 단위 확장) | **부분 채택** | 웹 대응물은 rem + `clamp()`. 현재 px 고정이라 리스크 있음. 6절 참조 |
| SF Pro / 시스템 폰트 | **기각** | 타이포가 브랜드 자체다. Rule 11 |
| 시스템 머티리얼 · 라운드 코너 · 반투명 | **기각** | 매트릭스 브루탈리즘과 정면 충돌 |
| 탭 바 / 네비게이션 스택 | **기각** | 웹 라우팅 2개(`/`, `/vote`)로 충분 |

스킬 오케스트레이션도 같은 규칙을 적용했다. `ui`/`ux`/`design` 키워드로 걸리는 스킬은 약 25개다.
`minimalist-ui`("그라디언트 금지")와 `industrial-brutalist-ui`("극단 대비"), `design-taste-frontend`("`#000000` 절대 금지")는 서로, 그리고 이 코드베이스와 충돌한다.
실행한 것: `redesign-existing-projects`(감사), `ui-ux-pro-max`(접근성·터치·성능), `design-taste-frontend`(상태 완결성), `web-design-guidelines`(코드 준수 체크리스트).
기각한 것: 스타일 계열 전부. 이 사이트는 이미 확정된 시각 언어를 갖고 있다.

## 2. 계층 구조

3단계만 쓴다. 더 깊어지면 현장에서 못 읽는다.

```
L1  이벤트 정체성   h1 clamp(68→148px) · Neue Machina · tracking -.055em
L2  섹션            h2 clamp(54→108px) · 1px hairline rgba(248,247,247,.18)
L3  레코드          22px strong / 17px time / 13px eyebrow
```

색은 계층을 만들지 않는다. **크기와 헤어라인이 만든다.** 액센트 `#caff5d`는 오직 "지금 행동 가능"에만 쓴다.

### 단위 규칙

| 대상 | 단위 | 이유 |
|---|---|---|
| `font-size` | `rem` | 브라우저 폰트 설정을 따라야 한다. WCAG 1.4.4 |
| `line-height` | 무단위 | 폰트 크기에 비례 |
| `padding` `margin` `gap` | `px`, **4의 배수** | Apple 8pt / Material 4dp와 같은 절대 그리드 |
| 유동 타이포 | `clamp(rem, vw, rem)` | 경계값은 폰트 설정을, 중간값은 뷰포트를 따른다 |

`rem` 환산은 루트 16px 기준이다. `13px → .8125rem`, `16px → 1rem`, `24px → 1.5rem`.
스냅 규칙은 **가장 가까운 4배수, 동점은 위로, 0으로는 내리지 않음**이다. 예외는 `(100vw - 1508px) / 2` 형태의 중앙정렬 거터 5곳으로, 결과가 뷰포트에 따라 연속이라 양자화가 성립하지 않는다.

| 토큰 | 값 | 용도 |
|---|---|---|
| ground | `#000` | 페이지 바닥 |
| body | `#f8f7f7` | 본문 |
| muted | `rgba(248,247,247,.72)` | 리드 문단 |
| secondary | `#a7a7a7` | 시간, 라벨 |
| hairline | `rgba(248,247,247,.18)` | 섹션 구분 |
| accent | `#caff5d` | skip link 포커스 링, 상승 |
| negative | `#e47467` | 하락, 실패 |

## 3. 네비게이션과 제스처

**모델: 평면 2라우트 + 탭 3개.** 스택도 모달도 없다.

```
/            이벤트 허브 ─ 탭 1 PERP-DEX DAY
                        ├ 탭 2 REBOUNDX IN WONDERLAND
                        └ 탭 3 TOKEN2049 SIDE EVENT
/vote        예측마켓 (히스토리 back으로 허브 복귀)
```

### 제스처 규칙
HIG는 제스처마다 비제스처 대안을 요구한다. Web Interface Guidelines도 동일하다.

| 제스처 | 대안 | 상태 |
|---|---|---|
| 탭 좌우 스와이프 | ← → 방향키 (`HomePage.tsx` 키다운 핸들러), 탭 클릭 | 구현됨 |
| 스피커 hover | 클릭, 포커스 | **이번에 추가** |
| 차트 스크럽 | 레인지 버튼 (1H/6H/24H) | 구현됨 |
| 당겨서 새로고침 | 도입 안 함 (라이브 시뮬레이션이 자동 갱신) | 해당 없음 |

### 플랫폼 규칙
- `color-scheme: dark` 선언 완료. 네이티브 스크롤바·폼 컨트롤이 다크로 렌더된다.
- `<meta name="theme-color" content="#000000">` 선언 완료. iOS Safari 주소창이 페이지와 이어진다.
- `touch-action: manipulation` 전역 적용. 더블탭 줌 지연 제거.
- `min-width: 320px` 보장. iPhone SE 세로에서 가로 스크롤 없음.
- 풀블리드 섹션은 `env(safe-area-inset-*)` 미적용. **미해결**, 노치 기기 가로 모드에서 확인 필요.

```
│ edgeX   Yes  10 @ 34   340 → 상태 +12    │
```

- 빈 상태가 다음 행동을 지시한다. "아무것도 없음"으로 끝내지 않는다.

### S7 · 리더보드

```
┌──────────────────────────────────────────┐
│ TRADER LEADERBOARD          <table>      │
│ #   HANDLE          PILL      Δ          │
│ 01  ▚ neo_0x91      4,120    +812        │
│ 02  ▚ trin1ty       3,940    −204        │
└──────────────────────────────────────────┘
```

- 진짜 `<table>` + `<thead>` + `<tbody>`. VoiceOver 테이블 탐색이 작동한다.
- **`<caption>` 없음.** 표의 목적이 스크린리더에 전달되지 않는다. 미해결, 10절.
- 행 수 상한이 코드에 없다. 데이터가 커지면 Web Interface Guidelines의 가상화 임계(>50)를 넘는다. 미해결.
- 상승/하락은 색 + 부호 둘 다. 색맹 대응.

### S8 · 정산 완료

```
┌──────────────────────────────────────────┐
│ MARKET SETTLED                           │
│ Winner: Lighter                          │
│ Your payout: 1,000 PILL                  │
│ 티켓 disabled, 사유 표시                  │
└──────────────────────────────────────────┘
```

- 종료 후에도 차트와 리더보드는 남는다. 결과를 확인하러 오는 사람이 있다.
- 티켓은 제거하지 않고 비활성 + 사유. 사라진 UI는 버그처럼 보인다.

## 5. 컴포넌트 사양

### 버튼
| 종류 | 스펙 | 상태 |
|---|---|---|
| Primary (`.outline-button`) | 1.5px `#f8f7f7`, radius 4px, min-height 56px, padding 0 32px | hover: bg .12 + `translateY(-2px)` / active: 없음 / focus-visible: 아웃라인 / disabled: opacity |
| Tab (`.event-tab`) | min-height 76px / 68px(≤1100) / 58px(≤700), 활성 시 상단 2px 바 + 화살표 노출 | hover / active `translateY(1px)` / focus-visible inset 아웃라인 |
| Row (`.speaker`) | 전폭, 헤어라인 하단, 활성 시 `translateX(-40px)` | `aria-pressed` |
| Skip (`.skip-link`) | 포커스 전 `translateY(-180%)`, 포커스 시 0 | focus-visible에서만 등장 |

전환 속성은 명시적으로 나열한다. `transition: all` 금지. 레이아웃을 유발하는 속성(`width`, `height`, `top`, `left`)은 애니메이션하지 않는다.
`.outline-button`은 `background`, `border-radius`, `opacity`, `transform` 4개를 전환한다. 앞의 둘은 페인트만 일으키므로 허용 범위다.

### 카드
카드를 최소화한다. 구분은 **1px 헤어라인**이 한다. `.outcome-row`, `.agenda-row`, `.speaker` 전부 박스가 아니라 선이다.
예외는 `.vote-brand-card` 하나. 여기만 실제로 z축 위에 뜬다.

### 폼
- 라벨 위, 값 가운데, 에러 아래.
- 숫자 입력은 `−` / `+` 스테퍼 동반. 모바일에서 키보드 없이 조작 가능.
- 붙여넣기 차단 없음.

### WCAG 2.2 AA 현황
| 기준 | 상태 | 비고 |
|---|---|---|
| 1.4.3 명암비 4.5:1 | **통과 (이번 수정)** | `#a7a7a7` 8.73:1 · `.72` 9.90:1 · `.55` 5.92:1. 비활성 탭 `.46`은 4.35:1로 **미달이었다**. `.5`(5.00:1)로 교정. P11 |

| 4.1.3 상태 메시지 | 통과 | 티켓 `role="status"`, 스켈레톤 `role="status"` |

### VoiceOver
- 탭 = `role="tab"` + `aria-selected` + `aria-controls`. 로터의 "탭" 항목에 나온다.
- 패널 3개 모두 `role="tabpanel"` + `aria-labelledby`. Wonderland 패널에 시각적으로 숨긴 `<h2>`를 넣어 로터 제목 목록의 구멍을 메웠다.
- 장식 SVG(`ArrowIcon`)는 `aria-hidden="true"`.
- 캔버스 배경(`DigitalRain`, `BlackHoleBG`)은 `aria-hidden`, `prefers-reduced-motion`에서 `display: none`.

### Dynamic Type: 웹 대응
HIG의 Dynamic Type에 해당하는 웹 동작은 **브라우저 기본 폰트 크기 변경 시 본문이 따라 커지는 것**이다.

`font-size` 176개를 전부 `rem`으로 옮겼다. 13개 레이어 전체, 잔여 px 0. `clamp()` 21개는 경계값만 `rem`으로 바꾸고 중간 `vw`는 그대로 뒀다.

```
font-size: 13px                    -> .8125rem
font-size: clamp(54px, 7vw, 108px) -> clamp(3.375rem, 7vw, 6.75rem)
```

**남은 한계.** `clamp()`의 중간값이 `vw`라서, 넓은 뷰포트에서는 폰트 설정을 키워도 헤드라인이 `vw` 값에 머문다. 경계에 닿을 때만 커진다. 완전히 따라가게 하려면 중간값을 `calc(1rem + 4vw)` 형태로 바꿔야 하는데, 그러면 현재 확정된 유동 곡선이 바뀐다. 본문·라벨·시간은 전부 반응하므로 1.4.4는 충족한다.

스페이싱은 `px`로 남겼다. 따라서 폰트를 200%로 키우면 글자만 커지고 여백은 그대로라 밀도가 올라간다. 스페이싱까지 `rem`으로 옮기는 것이 더 정확하지만, 4배수 그리드가 0.25rem 단위로 흩어지고 전 레이어를 다시 건드려야 한다. **미해결로 남긴다.**

## 9. Designer's Notes

**하나. `#000`은 실수가 아니다.**
`design-taste-frontend`와 `redesign-existing-projects` 둘 다 순수 검정을 금지한다. 일반적으로는 옳다. 오프블랙이 눈에 편하고 그림자를 받는다.
여기서는 기각했다. 매트릭스 테마의 그라운드이고, 행사장은 어둡고, OLED에서 진짜 검정이 픽셀을 끈다. 바꾸면 5개 레이어를 전부 건드린다. 이득보다 리스크가 크다.
**기각 조건**: 라이트 모드를 도입하거나, 그라운드 위에 실제 elevation 계층이 3단 이상 생기면 오프블랙으로 옮긴다.

**둘. hover는 절반의 인터랙션이다.**
스피커 행은 `onMouseEnter`만 있었다. 데스크톱에서는 우아하다. 폰에서는 아무 일도 안 일어난다. 이 행사의 관객은 대부분 폰을 든다.
`<button>` + `onClick` + `aria-pressed`로 바꾼 게 이번 작업에서 사용자 체감이 가장 큰 변화다. 시각적으로는 아무것도 안 바뀌었다.

**셋. 실패 상태가 없는 임베드는 시한폭탄이다.**
Wonderland 패널은 별도 빌드를 iframe으로 넣는다. 두 저장소의 배포가 어긋나는 순간 사용자는 960px 빈 화면을 본다. 에러 로그도 없다.
404가 `load` 이벤트를 발생시킨다는 점 때문에 `onError`만으로는 못 잡는다. `body.childElementCount === 0`이 실무적으로 유일한 신호였다.
**기각 조건**: 임베드를 없애고 Wonderland를 네이티브 React 페이지로 옮기면 이 코드 전체가 불필요해진다. 그게 더 나은 종착지다.

**넷. "준비 중"은 콘텐츠 부채다.**
TOKEN2049 히어로는 상세 정보가 준비 중이라고 말하면서 바로 아래에 6행 타임테이블, 4개 사실, 예측마켓 CTA를 보여주고 있었다. 사용자는 둘 중 하나를 믿는다. 보통 화면 위쪽을 믿는다.
플레이스홀더 문구는 만료일을 갖고 태어나야 한다.

**다섯. 숫자를 확인하다가 결함이 나왔다.**
문서에 명암비를 적으면서 실측했더니 비활성 탭이 4.35:1이었다. 16px 본문 크기라 large text 예외가 안 된다. AA 미달이고, 3개 랜딩 페이지 전부의 탭 바다.
스펙을 쓰지 않았으면 못 찾았을 결함이다. 문서 작업의 실제 값은 와이어프레임이 아니라 여기 있었다.
**기각 조건**: 자동 명암비 검사를 CI에 넣으면 이런 수동 확인은 불필요해진다. jsdom은 CSS 값을 계산하지 않아서 현재 테스트로는 못 잡는다.

**여섯. 확인하지 못한 것.**
브라우저 검증을 못 했다. 샌드박스가 localhost를 막고 Playwright 바이너리가 없다.
검증한 것은 `tsc --noEmit`, `vitest run` 33개, `vite build`, 그리고 `dist/` 산출물 grep이 전부다. **레이아웃은 눈으로 확인되지 않았다.**
특히 skip link의 포커스 위치, 스켈레톤 5행의 세로 배분, 44px 타깃 적용 후 푸터 높이는 실제 브라우저에서 봐야 한다.

**이번 변경은 특히 눈으로 봐야 한다.** `font-size` 176개와 스페이싱 71개를 한 번에 옮겼다. 타입체크와 33개 테스트는 통과하지만, 둘 다 CSS 값을 읽지 않는다. 최대 2px씩 어긋난 여백이 누적되면 좁은 구간에서 줄바꿈이 달라질 수 있다. 701–1100px 구간과 ≤420px 구간을 먼저 보는 걸 권한다.
